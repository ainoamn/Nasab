# نَسَب (Nasab) — منصة شجرة العائلة العربية

## التشغيل المحلي

### المتطلبات

- Node.js 20+
- npm

### الخطوات

```bash
cd app
npm install
cp .env.example .env
# عدّل .env حسب الحاجة (انظر app/.env.example)
npm run db:push
npm run dev
```

يفتح التطبيق على: **http://localhost:5173**

### دخول التطوير المحلي

عند تفعيل `DEV_LOCAL_AUTH=true` في `.env`:

| الحقل | القيمة الافتراضية |
|-------|-------------------|
| المستخدم | `admin` |
| كلمة المرور | `admin123` |

> هذا الحساب يحصل على دور **مشرف (admin)** — للتطوير فقط، ويُعطّل تلقائياً في الإنتاج.

### أوامر مفيدة

```bash
npm run dev          # خادم التطوير
npm run build        # بناء الإنتاج
npm run start        # تشغيل الإنتاج (بعد build)
npm run check        # فحص TypeScript
npm run db:push      # تطبيق schema على قاعدة البيانات
npm run db:generate  # توليد migrations
npm run db:migrate   # تشغيل migrations
```

    ├── src/

    │   │   ├── tree/         ← FamilyChart + موصلات الخطوط
    │   │   ├── print/        ← قوالب الطباعة
    │   │   └── ui/           ← shadcn
    │   ├── lib/              ← familyGraph, printData, lineageParser…
    │   ├── i18n/             ← ar.ts + en.ts

## الميزات الرئيسية

### 1. شجرة العائلة

- إنشاء أشجار متعددة لكل مستخدم
- إضافة وتعديل الأفراد (اسم، كنية، لقب، تواريخ، مكان، صورة، ملاحظات)
- **ربط القرابة**: ابن، بنت، أخ، أخت، زوج/زوجة، فرع خارجي
- **فصل الربط**: من بطاقة الشخص → قسم «الروابط العائلية» → زر «فصل الربط» (أب/أم/زوج/أبناء) دون حذف الشخص
- مخطط شجرة تفاعلي مع:
  - رأس موقع العائلة (غلاف + إحصائيات + نبذة + مؤشر اكتمال)
  - أوضاع متعددة: عرض العائلة / العائلة القريبة / مخطط الأسلاف / الأحفاد / مظهر مروحي
  - فلتر الزيجات المتعددة في عرض العائلة
  - شريط مناسبات (أعياد ميلاد وذكريات زواج)
  - بحث سريع، خط زمني، قائمة + لاختيار صلة القرابة، وخانات أب/أم قابلة للنقر
  - بحث فوري بترتيب شخصي (بيت/مفضلة/أخيرون) وشارة قرابة للمحور
  - تبويب صور مرتّب شخصياً + تسميات قرابة + فلاتر في القائمة
  - تبويبا **الأماكن** و**المناسبات** مع قفز للمخطط وطباعة القوالب
  - شارة قرابة تحت اسم الملف تفتح إبراز المسار بنقرة
  - بطاقات عمودية بأسلوب عائلي وخطوط متعامدة بلا أسهم + معاينة عند التحويم + نقر مزدوج للتركيز + نقاط بحث كهرمانية
  - بانر **مناسبات اليوم** + طباعة/نسخ رابط من شريط المناسبات
  - نفس معاينة التحويم/التركيز في مخطط الأسلاف والأحفاد، وتلميح القرابة في المظهر المروحي
  - روابط زواج قابلة للتعديل مباشرة من المخطط
  - لوحة تفاصيل جانبية مع شريط العائلة المباشرة ونواقص الملف وتنقّل الإخوة (أزرار + ←→) وخط زمني قابل للنقر
  - **مسار من شخص البيت** hops قابلة للنقر مع إبراز المسار
  - **أظهر على المخطط** من القائمة والتفاصيل مع توسيط فوري
  - **روابط عميقة** للشخص (مساحة العمل / مشاركة عامة / جذر الطباعة) مع نسخ الرابط
  - شريط **المفضلة** + قائمة **نمو الشجرة** + تفصيل مؤشر الاكتمال
  - لوحة **اكتشافات** قابلة للإخفاء ومرتّبة قرب شخص البيت
  - أداة **كيف يرتبطان؟** مع نسخ رابط المسار العميق `?person=&relate=`
  - **جولة بحث** فوق المخطط (إصلاح/إظهار/تخطّي + `N`)
  - مناسبات: تنزيل تقويم `.ics` ونسخ تهنئة مع الرابط
  - **نسخ نص المسار** و**بطاقة الشخص** للمشاركة في واتساب
  - نطاق مناسبات (دائرتي / مفضلة / الكل) + تقويم ٩٠ يوماً بملف واحد
  - مشاركة عامة أغنى (مسار قرابة + بطاقة/عائلة مباشرة)
  - مناسبات حيّة على صفحة المشاركة + ملفّان في «كيف يرتبطان؟»
  - جولة بحث بنطاق دائري واستئناف الفهرس
  - ملخص عائلي بأولويات بحث + شهادة قرابة للطباعة + نطاق مناسبات على /share
  - جد مشترك على المسار + ورقة ملف للطباعة + مقارنات قرابة مثبتة
  - طباعة على /share + شريط مقارنات مثبتة + جولة اتساق (`C`)
  - ذكرى وفاة في المناسبات + بطاقة طباعة + شريط مقارنات أخيرة
  - واتساب بنقرة للتهاني/المسار + تقويم كامل على /share + ورقة ملخص للطباعة
  - عمر وترتيب في العائلة المباشرة + تصدير vCard/JSON + اكتشافات على /share
  - شريط إخوة بالميلاد + أماكن على /share + واتساب لبطاقة الشخص والملخص
  - رمز QR + معرض صور على /share + CSV مناسبات + واتساب نواقص الملف
  - مخططات متعددة على /share + اكتمال شفاف + دليل نمو للقراءة فقط
  - مقارنات قرابة أخيرة + ملخص عائلي للنسخ
  - **شخص البيت** + **سجل التركيز** للتنقّل السريع
  - توسيط المحدد وملاءمة عرض المخطط
  - تحكم بعدد الأجيال + وضع ملء الشاشة للمخطط
- استيراد Excel جماعي
- **تصدير واستيراد GEDCOM 5.5.1** للتوافق مع برامج الأنساب
- اختصارات لوحة مفاتيح (`/`، `Esc`، `H`، `R`، `←→`، `?`) + شريط «شاهدتهم مؤخراً»
- طباعة PDF عبر **13 قالباً** (نخلة، مخطوط، كتاب، ملصق، خريطة، فخذ، مناسبات، مزخرف، مروحة، شمس نسب، كلاسيكي، نسب أعمدة، تراث) مع تحديد نطاق الأجيال/الفرع
- سجل تغييرات (Audit log) لكل شجرة

### 2. الخصوصية والعرض

- مستويات خصوصية للفرد: خاص / عائلة / مرتبط / عام
- إعدادات الشجرة: إخفاء الأحياء، عرض الإناث (كامل / الاسم الأول / إخفاء)
- رؤية الشجرة: خاصة / غير مدرجة / عامة
- صفحة مشاركة عامة `/share/:id` مع فلترة الخصوصية للزوار

### 3. الأعضاء والدعوات

- أدوار: **مالك / مشرف / محرر / مشاهد**
- دعوة بالرابط مع token آمن وتاريخ انتهاء
- قبول الدعوة من `/invite/:token`

### 4. إدارة الشجرة (Dashboard)

- **إيقاف مؤقت (paused)**: عرض فقط — لا تعديل
- **أرشفة (archived)**: إخفاء كامل — المالك يستعيد من لوحة التحكم
- **حذف نهائي** للشجرة (مع تأكيد)
- إظهار/إخفاء الأشجار المؤرشفة

### 5. حذف الأفراد (Soft delete)

- حذف ناعم عبر `deletedAt` — يختفي من الشجرة والإحصائيات
- *(استرجاع الأفراد المحذوفين: غير مُنفَّذ بعد)*

### 6. حساب المستخدم `/account`

- الملف الشخصي والعنوان وبريد الفوترة
- عرض الاشتراك وتواريخ البداية/الانتهاء
- استخدام الخطة (أشجار، أفراد، حدود)
- **كود خصم** و**رمز إحالة**
- الفواتير (تحميل كسول عند فتح تبويب الدفع)

### 7. أرقام متسلسلة

| النوع | الصيغة | مثال |
|-------|--------|------|
| المستخدم | `USR-000001` | تلقائي |
| الفاتورة | `INV-000001` | عند إنشاء فاتورة |
| الإحالة | `NSB00001` | من رقم المستخدم |

### 8. الاشتراكات

| الخطة | الوصف |
|-------|-------|
| **مجانية** | حتى 500 فرد، دعوات، PDF أساسي |
| **نَسَب بلس** | أفراد بلا حدود، قوالب طباعة، أرشيف |
| **الطباعة** | طلبات طباعة حسب الحاجة |

- حساب تلقائي لـ **تاريخ بداية/انتهاء** الاشتراك حسب مدة الباقة (`periodDays`)
- **خصم التجديد** (`renewalDiscountPercent`) قابل للضبط من المشرف
- **مكافأة الإحالة**: +30 يوماً للمُحيل عند اشتراك المُدعو ودفع فاتورته

### 9. الكوبونات والخصومات

- أكواد نسبة مئوية أو مبلغ ثابت
- تنطبق على: اشتراك جديد / تجديد / الكل
- تُطبَّق عند إتمام الدفع (لا تُستهلك مسبقاً)

### 10. بوابات الدفع

| البوابة | النوع |
|---------|-------|
| **Thawani** | Checkout hosted (عُمان) |
| **Stripe** | Checkout Session |
| **PayPal** | Orders API |
| **تحويل بنكي** | تعليمات + فاتورة معلقة |
| **يدوي** | تأكيد من المشرف |

- لوحة المشرف: شبكة بطاقات بشعارات — الضغط يفتح `/admin/gateways/:slug`
- صفحة checkout: `/checkout?plan=plus`
- Webhooks: `/api/webhooks/{thawani,stripe,paypal}`

### 11. تسجيل الدخول

- **Kimi OAuth** (الأساسي)
- **Google OAuth** (اختياري — `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET`)
- **دخول محلي** (تطوير فقط)

## قاعدة البيانات

### جداول رئيسية

- `users` — حسابات، خطة، إحالة، حظر، IP
- `trees` — أشجار + حالة (active/paused/archived)
- `persons` — أفراد + soft delete
- `relationships` — قرابة (أب/أم/زوج)
- `tree_members` — أعضاء وأدوار
- `invites` — دعوات
- `change_logs` — سجل التغييرات
- `subscription_plans` — خطط وحدود
- `invoices` — فواتير + gateway + plan
- `coupons` / `coupon_redemptions` — خصومات
- `payment_gateways` — إعدادات البوابات
- `platform_sequences` — ترقيم USR/INV
- `expenses` — مصروفات المحاسبة

### التطوير vs الإنتاج

```env
# تطوير (SQLite)
DATABASE_URL=file:./.data/dev.sqlite

# إنتاج — Neon PostgreSQL (موصى به مع Vercel)
DATABASE_URL=postgresql://user:pass@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require

# أو إنتاج — MySQL (Docker)
DATABASE_URL=mysql://user:pass@host:3306/nasab
```

الجداول تُطبَّق عبر:

```bash
cd app
npm run db:push
```

## الأمان والأرشفة

### طبقات الحماية الموجودة

- JWT في cookie `httpOnly` + `secure` (HTTPS)
- tRPC middleware: مصادقة + حظر المستخدم
- RBAC: admin على المنصة + أدوار على الشجرة
- أرشفة/إيقاف الشجرة يُطبَّق على API
- Drizzle ORM (حماية SQL injection)
- Zod للتحقق من المدخلات
- دعوات: token عشوائي + انتهاء صلاحية
- توقيع webhooks للبوابات + ربط جلسة الدفع بالفاتورة
- OAuth `state` موقّع + `ALLOWED_ORIGINS`
- Rate limiting على login / OAuth / webhooks / الدعوات
- Security headers

## النشر للإنتاج

الدليل التفصيلي: [`app/DEPLOY.md`](app/DEPLOY.md)

### Checklist سريع

- [ ] `NODE_ENV=production`
- [ ] `APP_SECRET` قوي (≥ 32 حرفاً)
- [ ] `DATABASE_URL` → Neon PostgreSQL أو MySQL (ليس SQLite)
- [ ] `OWNER_UNION_ID` للمشرف الأول
- [ ] `APP_PUBLIC_URL` + `ALLOWED_ORIGINS` على HTTPS
- [ ] `npm run build` مع `VITE_*`
- [ ] تفعيل بوابة دفع + webhooks
- [ ] `npm run prod:check` داخل `app/`
- [ ] **عدم** تفعيل `DEV_LOCAL_AUTH`

### Vercel + Neon

1. Root Directory في Vercel: `app`
2. أضف متغيرات البيئة (Production): `DATABASE_URL`, `APP_ID`, `APP_SECRET`, `KIMI_*`, `VITE_*`, `APP_PUBLIC_URL`, `ALLOWED_ORIGINS`, …
3. البناء (`npm run build`) يولّد الواجهة في `dist/public` ودالة API في `api/index.js`
4. طبّق الجداول مرة واحدة محلياً أو من CI: `DATABASE_URL=postgresql://... npm run db:push`

### Docker

```bash
cd app
cp .env.production.example .env
# املأ الأسرار ثم:
docker compose up -d --build
```

### بدون Docker (VPS)

```bash
cd app
npm ci && npm run build
npm run db:push
NODE_ENV=production npm start
```
